# 双线激光、双相机标定与扫描系统需求

## 1. 已确认硬件

| 设备 ID | 激光 | 鲁班猫 4 V1 TTL | 相机与镜头 | 标定状态 |
| --- | --- | --- | --- | --- |
| `scanner_450` | 450 nm | 物理 Pin 11 / GPIO0_B7 / Linux GPIO 15 | 130 万相机、12.5 mm 镜头 | 已固定，尚未标定 |
| `scanner_650` | 650 nm | 物理 Pin 7 / GPIO0_C0 / Linux GPIO 16 | 160 万相机、6 mm 镜头 | 内参、激光平面、手眼均已标定，设备未移动 |

`scanner_650` 绑定已标定相机 `MV-CS016-10GM / DA8784601`，最近实机枚举地址为
`192.168.7.45`。`scanner_450` 的 IP、型号和序列号尚无可信记录，不能推测填写。

现有正式文件：

- `config/hik_intrinsics.yaml`
- `config/hik_laser_plane.yaml`
- `config/hik_handeye.yaml`

只属于 `scanner_650`。任何情况下都不允许 `scanner_450` 回退加载这三份文件。

## 2. 功能需求

### R1：两组标定完全隔离

1. 标定程序必须明确显示当前设备 ID、波长、镜头、TTL 引脚和相机身份。
2. 两组设备分别保存内参、激光平面、手眼参数和原始样本。
3. 每个标定会话从创建开始即绑定一个设备，不允许在会话中热切换设备。
4. 实时样本必须记录设备 ID、预期相机身份和实际相机身份。
5. 连接相机后必须检查序列号。错误相机只能预览，不能写入正式标定。
6. `scanner_450` 未完成三项标定时，扫描程序必须明确显示缺失项并禁止三维建图。
7. 更新某设备的内参，只能使该设备的激光平面和手眼依赖失效，不能影响另一设备。
8. 现有 `scanner_650` YAML 内容和 SHA-256 依赖链必须保持兼容。

设备目录：

```text
data/calibration/
├── scanner_450/session_...
└── scanner_650/session_...

config/
├── hik_intrinsics.yaml          # scanner_650 已有正式标定
├── hik_laser_plane.yaml         # scanner_650 已有正式标定
├── hik_handeye.yaml             # scanner_650 已有正式标定
├── synchronization.yaml         # scanner_650 已有同步配置
└── devices/scanner_450/
    ├── hik_intrinsics.yaml
    ├── hik_laser_plane.yaml
    └── hik_handeye.yaml
```

### R2：GUI 免密码控制两路 TTL

1. 日常启动、连接、开光、关光、状态查询和退出均不得弹出 SSH 或 sudo 密码。
2. GUI 不得调用现有交互式 `sudo bash` 调试脚本。
3. 板端守护进程是 GPIO15、GPIO16 的唯一所有者。
4. 业务状态只有 `OFF`、`450_ON`、`650_ON`；默认禁止两束激光同时开启。
5. 切换波长时必须先关闭当前通道，再开启目标通道。
6. GUI 只有收到板端确认后才能显示“已开启”，不能用按钮点击状态冒充硬件状态。
7. GUI 退出、SSH 断开、网络异常、协议错误、心跳超时、守护进程停止时，两路必须自动拉低。
8. 扫描中光控连接故障时，必须中止扫描并请求 FR5 停止。
9. 板端启动时默认两路 LOW，且不得自动恢复上次开启状态。
10. 安装使用一次管理员认证；安装完成后的日常控制使用受限专用 SSH 密钥。

控制链路：

```text
Qt GUI
  └── 持久 ssh -T（BatchMode、固定主机密钥、受限专用密钥）
        └── forced-command gateway
              └── Unix socket
                    └── systemd line-laser daemon
                          ├── GPIO15 / 450 nm
                          └── GPIO16 / 650 nm
```

### R3：线扫 GUI 显示和管理两组设备

第一阶段采用“两组独立、一次扫描一组”：

1. GUI 同时提供 `scanner_450` 和 `scanner_650` 两个明确页面。
2. 每页有独立相机 IP、连接状态、相机身份、标定状态、激光状态、图像预览、扫描表格、日志和输出目录。
3. 任一真实扫描开始后，另一设备页面禁止启动真实扫描。
4. 当前设备对应的激光未确认开启时，不允许机器人运动或采图建图。
5. 扫描完成、用户停止或异常终止时自动关光。
   只有板端确认两路 LOW、FR5 由新鲜状态确认停止、相机 worker 空闲后，才能释放
   设备组互锁；任一项无法确认时按故障锁止。
6. 两组点云、图片、清单和同步诊断分别保存：

```text
data/scans/<device_id>/scan_.../
data/scan/<device_id>/sync_scan_.../
```

7. `scanner_450` 可在未标定时连接相机和测试 TTL，但不能生成三维点云。
8. 扫描清单必须记录设备 ID、波长、相机序列号、TTL 通道和三份标定文件哈希。
9. 每个会话必须原子写入 `session_result.json`，区分完整与中止并记录原因、结束时间、
   最终计数和终态互锁结果。

第二阶段才考虑“同一次机器人运动、两台相机严格同步采集”。它需要共享机器人时间线、每相机独立时钟映射、双相机启动/停止屏障、独立重建队列和带宽验收，不得通过把两台相机帧混入现有单相机同步会话来实现。

## 3. 架构边界

### 设备档案

`LineLaserDeviceProfile` 是设备身份和路径的唯一来源，至少包含：

- 稳定设备 ID 和显示名；
- 波长与 TTL 物理引脚；
- 默认/预期相机身份；
- 相机光学坐标系；
- 三份正式标定路径；
- 独立连续同步配置路径；
- 标定和扫描 session 根目录。

一个标定窗口实例和一个扫描页面实例只持有一个不可变 profile。

### 标定算法

`HikCalibrationCore`、`HandEyeCalibrationCore` 继续保持无设备全局状态。算法通过显式参数接收图像、内参、板定义、激光面和手眼变换，不为波长复制算法。

### 相机

每台海康相机有独立 `HikCameraWorker` 和线程、独立 handle、请求 ID 和帧状态。MVS SDK 的全局 `Initialize/Finalize` 必须由进程级引用计数管理，不能由任一 worker 单独关闭。

### 机器人

FR5 是进程级共享资源。标定程序和扫描程序各自只创建一个
`FairinoRobotSession`，由它独占唯一的 worker、线程和 `FRRobot`；两个 profile 页面
共享连接状态，并使用全局唯一请求 ID 定向接收结果。空闲切页不执行 `CloseRPC`，也
不建立第二个 SDK 客户端。手眼样本事务、真实运动、扫描和终端安全屏障通过独占命令
租约串行化；TTL LOW、FR5 停止和相机空闲全部确认前不得把租约交给另一页。受
FAIRINO 3.9.4 后台线程生命周期限制，主动断开或连接失败后仍需重启进程才能重连。

## 4. 安全不变量

1. 应用和板端启动默认关光。
2. 未知激光状态等同故障，不等同“已关闭”。
3. 未确认正式标定、相机 SN 或标定哈希时禁止三维扫描。
4. 450 nm 永远不得使用 650 nm 标定结果。
5. 两束激光默认互斥。
6. GPIO 只能作为 TTL 小电流逻辑输出，不能作为激光器电源。
7. 软件不能替代物理急停；TTL 输入建议增加硬件下拉。
8. 真运动仍需现有路径、速度、碰撞和急停确认。
9. `StopMotion()` 返回成功只表示命令被 SDK 接受；必须再由新鲜 20004 包连续确认
   `motion_done=1` 且 TCP 线/角速度接近零。确认超时不得解锁。

## 5. 验收标准

### 自动化验收

- 两 profile 的正式路径、session 根目录和 frame 均不冲突。
- 已有 650 nm 三文件仍能通过哈希、frame、SN 交叉校验。
- 450 nm 文件缺失时只禁用该页面建图，不影响 650 nm。
- 两个相机 worker 同时存在时，一个析构不会反初始化另一个正在使用的 MVS SDK。
- GPIO 守护进程启动为 LOW，450/650 映射正确且互斥。
- 控制连接 EOF、租约超时和守护进程停止都会进入 LOW。
- 任一真实扫描活动时另一页面不能启动真实扫描。
- 两设备输出目录互不覆盖。
- 正常完成和所有中止路径都必须通过 TTL、FR5、相机终态屏障并写入会话结果。

### 实机验收

1. 不接激光 TTL 负载，用万用表/示波器分别验证 Pin 11、Pin 7 的 HIGH/LOW 和切换毛刺。
2. 接入激光后分别验证 450 nm、650 nm，不允许通道串反。
3. 开光后关闭 GUI、拔网线和杀死 SSH 进程，确认租约超时后自动灭光。
4. 650 nm 完整回归已有标定和扫描精度。
5. 完成 450 nm 内参、激光平面、手眼后才能启用其三维建图。
6. 分别进行持续扫描的帧率、缺帧、CPU、内存、磁盘和网络带宽测试。

## 6. 尚待现场录入

`scanner_450` 的以下信息不能从“130 万相机”推断，必须连接实机后录入并绑定：

- 相机 IP；
- 型号；
- 序列号；
- 实际输出分辨率；
- 合理曝光/增益；
- 有效工作深度；
- 450 nm 光学系统对应的条纹阈值和正式质量门槛。

当前实现不会猜测或持久化空白的 450 相机 IP；现场每次启动先手工输入。型号和序列号
会随该 profile 的正式标定绑定。后续如需持久化 IP，应增加独立设备配置或 `QSettings`，
不得写入 650 profile。
