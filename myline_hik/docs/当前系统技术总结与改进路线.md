## 1. 总体结论

当前系统已经完成了从“标定工具”到“可以连续输出点云”的主体链路：

```text
海康相机 60 fps
  -> FrameID、设备时间戳、曝光时间
  -> 相机设备时钟映射到 CLOCK_MONOTONIC_RAW
  -> 曝光中点时刻

FR5 20004 实时状态
  -> SDK RecvPkg 成功返回处记录 CLOCK_MONOTONIC_RAW
  -> robotTime 映射到 CLOCK_MONOTONIC_RAW
  -> 前后位姿样本

曝光中点
  -> XYZ 线性插值 + Quaternion SLERP
  -> 激光中心提取
  -> 相机射线与激光平面求交
  -> T_base_flange · T_flange_camera
  -> base_link 原始点云与体素点云
```

从最近实测看，采集吞吐和软件同步架构已经基本稳定：

- 相机实测约 `59.982 fps`，FrameID 无跳变；
- FR5 完整包实测约 `83.33 Hz`，周期约 `12 ms`；
- SDK 逐包序号无缺口；
- 图片内存池、图片写盘队列、同步队列和重建队列均无溢出；
- 两个重建线程处理一帧约 `9–12 ms`，能够跟上 60 fps；
- 有效帧已经能够自动生成 `continuous_raw.ply` 和 `continuous_voxel.ply`。

2026-07-23 又完成了两项重要改动和一次初步尺寸验证：

- 激光平面 GUI 已加入 `300/400/550/700/850/1000 mm` 六档采集引导；
- 修正了近距离饱和平顶条纹的中心偏移：从“以下降沿为峰值的固定窗口”
  改为“完整半高宽区间灰度质心”；
- 同一批 50 姿态原图重算后，平面内点率由 `88.58%` 提升到 `94.78%`；
- 移除两组低质量姿态后，48 姿态结果为内点率 `95.66%`、RMS
  `0.1097 mm`，覆盖 Z=`288.33–1025.05 mm`；
- 使用游标卡尺 100 mm 进行一次连续点云人工选点，得到
  `99.173854 mm`，误差 `-0.826146 mm/-0.826%`。这是一条有价值的整机
  观测，但高反光、人工端点选择和仅一次测量使它尚不能作为尺度修正依据。

但当前还不能把标定残差或“点云大致形状正确”直接表述成整机测量精度。尚未完成的关键工作是：

1. 只有一次 100 mm 卡尺人工选点结果，没有使用可溯源量块/长度标准、
   拟合几何特征和重复正反扫建立整机精度报告；
2. 相机时间戳究竟代表曝光开始还是其他相机事件仍未被硬件实验确认；
3. `camera.fixed_time_offset_us` 仍为 `0`，固定时延尚未标定；
4. 手眼标定虽然通过软件门槛，但其残差已成为当前主要误差嫌疑；
5. 高反光/过曝只做了基础抑制和告警，没有自动拒绝、降曝光、换姿态或重扫闭环；
6. 当前点云只做深度范围过滤和体素降采样，缺少置信度、时序、空间离群点等质量过滤；
7. 当前激光配置来自离线候选，300 mm 档为 `4/5`，且新会话无法验证原始
   off/on 的相机身份与曝光元数据；
8. J6 纯旋转建图在几何上可行，但当前只实现 MoveL 和线速度恒速判断；
9. 系统尚无硬件同步、碰撞规划、ROS 2 点云发布和实时可视化。

因此，当前系统更准确的定位是：

> **具备稳定连续采集、软件时间同步和点云生成能力的工程原型；尚未完成计量级验收，也尚未完成高反光鲁棒闭环。**

以下数值必须区分：

- **拟合残差**：标定模型对参与拟合数据的内部一致性；
- **重复性**：相同条件重复测量的离散程度；
- **绝对精度**：相对于可溯源标准件真值的误差；
- **点云分辨率/点间距**：采样密度，不等于精度。

当前已有较完整的拟合残差和同步统计，并出现了第一条长度真值对比，但
100 mm 卡尺属于高反光工件，测量采用人工端点且没有重复统计，因此仍不能给出
可信的整机绝对精度或直接计算全局尺度修正。


它能运行在千兆网中，但带宽余量不大。

### 3.3 网络上尚未做好的地方

实机日志显示相机设置了 `GevSCPSPacketSize=8164`，但 `enp4s0` 当前 MTU 是 `1500`。这会导致大 UDP 数据报被 IP 分片，或者由链路中的某一层做额外处理。

目前接口统计为零丢包，连续扫描也没有 FrameID 缺口，因此它尚未造成可见故障；但在长时间扫描、系统高负载或链路增加交换机后，会增加抖动与丢帧风险。

建议：

1. 如果相机为直连且网卡、线缆和交换设备全部支持 Jumbo Frame，将 `enp4s0` MTU 统一设置为 `9000`；
2. 如果链路中任何设备不支持 Jumbo Frame，则把相机包长限制到与 MTU 一致的安全值；
3. 设置后进行至少 30 分钟满幅 60 fps 压力测试，检查 FrameID、`nLostPacket`、网卡 dropped/missed 和应用队列；
4. 不要只修改一端；相机包长和整条链路 MTU 必须一致。

## 4. 软件系统现状

当前目录是独立 CMake/Qt5 C++17 工程，不是 ROS 2 package，也不通过 colcon 构建。

已经生成：

- 标定 GUI：`HikLineLaserCalibration`
- 停稳/连续扫描 GUI：`HikConstantLaserScan`
- 内参、激光平面、手眼、同步、点云核心库
- PLY、CSV、JSON、PNG 原始记录
- 3 项核心自动测试：标定、同步、连续重建

尚未生成：

- ROS 2 `sensor_msgs/Image`、`CameraInfo` 和 `PointCloud2`
- TF 发布
- RViz 实时显示
- 在线点云质量面板
- 自动轨迹规划与碰撞检查
- 相机、FR5 和完整运动链路的自动化硬件在环测试

### 4.2 相机采集链路

连续模式使用：

```text
MV_CC_RegisterImageCallBackEx
  -> 读取 FrameID、设备时间戳、尺寸、像素格式、曝光和丢包字段
  -> CLOCK_MONOTONIC_RAW 回调时刻
  -> 从固定容量 ImageBufferPool 取缓冲
  -> 复制 Mono8 图像
  -> 有界相机队列
```

已做好的部分：

- 自动曝光和自动增益关闭；
- 固定 60 fps、固定曝光和增益；
- 使用 `nFrameNum` 检查帧连续性；
- 使用 `nDevTimeStampHigh/Low`；
- 从 `GevTimestampTickFrequency` 获取设备时钟频率；
- 拒绝非 Mono8、长度不足和 `nLostPacket != 0` 的帧；
- 相机回调不进行 PNG 压缩、条纹提取或点云生成；
- 固定容量图像池防止无界分配；
- 两个独立 PNG 写盘线程，压缩级别 1。

当前不足：

- 每帧仍要从 SDK 缓冲复制约 1.56 MB，60 fps 约 93 MB/s 内存复制；
- 图像池内部使用互斥锁，入口不是严格 wait-free；
- `scanner_650` GUI 默认 IP 已统一为最近实机枚举的 `192.168.7.45`；
- 没有保存 ROI、包长、MTU、网卡、MVS 版本和 Git 提交等完整运行指纹；
- 没有长时间设备在环自动测试；
- PNG 适合追溯但不适合小时级连续采集，长扫描需要更高效的原始分块格式或可配置保存策略。

### 4.3 FR5 实时状态链路

FAIRINO 3.9.4 原 SDK 没有公开 20004 每包到达回调。本工程补丁已经在 SDK 的接收线程中：

1. 完整包接收成功后立即记录 `CLOCK_MONOTONIC_RAW`；
2. 为每个完整包生成 SDK 接收序号；
3. 保存互斥保护的一致快照；
4. 调用轻量回调；
5. 应用侧通过容量 1024 的 SPSC 队列交给独立消费线程。

已做好的部分：

- 到达时间位于 `RecvPkg()` 成功返回处，而不是 Qt 定时器；
- 每个完整包生成一个样本；
- `frame_cnt` 只用于控制器内部计数诊断；
- SDK 接收序号用于判断应用链路是否丢包；
- 完整包包含关节角、法兰位姿、TCP 速度和 `robotTime`；
- `GetRobotRealTimeState()` 只用于一致快照与耗时诊断；
- getter 实测均值约 `1–2 us`、P99 约 `3–5 us`、最大约 `7–10 us`，没有阻塞证据；
- 请求周期 10 ms、实际完整包约 12 ms/83.33 Hz 已按控制器实际行为接受；
- 当前实测 SDK 序号缺口为 0。

当前不足：

- SDK 是本地补丁版本，升级 SDK 时需要重新审计、重新打补丁和重新做 ABI/压力测试；
- 官方 SDK 后台线程没有公开 join，进程内断开后不能安全重连，当前采用“重启应用”的规避方式；
- 应用层 `pushRobot()`/`pushCamera()` 仍会取得生命周期互斥锁，严格意义上不是完全无等待入口；
- 没有设置线程 CPU 亲和性、实时调度优先级或内存锁定；当前负载下没有丢包，但高负载确定性仍未验证；
- 没有读取并记录机器人安全状态、碰撞状态和急停链路，当前运动控制不属于安全控制系统。

### 4.4 同步和位姿插值

当前同步策略是：

```text
相机设备时钟 --滑动仿射拟合--> 主机 CLOCK_MONOTONIC_RAW
FR5 robotTime --滑动仿射拟合--> 主机 CLOCK_MONOTONIC_RAW

相机参考时刻
  -> 根据 timestamp_reference 推算曝光开始
  -> 加 0.5 × exposure 得到曝光中点
  -> 加 fixed_time_offset
  -> 在机器人环形缓冲中找前后样本
  -> XYZ 线性插值
  -> Quaternion SLERP
```

已做好的部分：

- 主时间轴统一为 `CLOCK_MONOTONIC_RAW`；
- 相机和机器人均保留原始时钟与主机时钟；
- 时钟映射不稳定时明确回退；
- 机器人姿态不对 RPY 直接线性插值；
- FR5 固定轴 RPY 约定明确为 `Rz * Ry * Rx`；
- 前后 SDK 包序号不连续时同步无效；
- 机器人跨度超过 25 ms 时同步无效；
- 加减速段保存但默认不参与有效建图；
- 速度判断结合反馈速度滑动中值与位置拟合；
- 每帧同步结果和无效原因写入 CSV。

当前最重要的同步风险：

1. MVS 头文件没有说明设备时间戳对应曝光开始、曝光结束还是其他相机事件；
2. 配置目前假定 `timestamp_reference: exposure_start`，尚未用曝光输出、示波器或成像实验确认；
3. `camera.fixed_time_offset_us: 0.0`，固定偏差尚未通过正反向扫描标定；
4. `robotTime` 只有毫秒级字段，当前映射残差 RMS 约 2 ms；
5. 软件同步可以消除大部分网络到达抖动，但不能替代硬件触发或共同硬件时钟。

### 4.5 激光条纹和三维重建

当前常亮单帧重建算法：

```text
Mono8
  -> 31×3 与 3×31 形态学开运算估计背景
  -> 取两个背景估计的较小值
  -> 原图减背景
  -> 原始灰度 < 60 的区域清零
  -> 每行/每列寻找局部峰
  -> 扩展完整半高宽区间并限制最大宽度
  -> 完整半高宽区间灰度质心亚像素中心
  -> 选择点数更多的横向或纵向结果
  -> 去畸变射线与激光平面求交
  -> 深度范围过滤
```

扫描程序覆盖参数：

| 参数 | 当前值 |
| --- | ---: |
| 最小响应差 | 10 |
| 自适应阈值 | 均值 + 2×标准差 |
| 最少条纹/三维点 | 80 |
| 最大条纹宽度 | 20 px |
| 最小置信度 | 0.05 |
| 背景核 | 31×3 和 3×31 |
| 最低原始灰度 | 60 |
| 相机 Z 有效范围 | 288.33–1025.05 mm（当前启用候选） |

已经具备：

- on/off 标定模式的严格差分；
- `laser-off` 板区域饱和率门槛 1%，`laser-on` 因窄激光线采用独立 5% 门槛；
- 常亮模式的局部背景抑制；
- 对窄条纹和近距离饱和平顶条纹统一使用完整半高宽灰度质心；
- 条纹宽度、响应、置信度和连续性约束；
- 畸变校正；
- 射线/平面三角测量；
- 平行射线、相机后方点、深度范围外点拒绝；
- PLY 中保留置信度、响应、帧号和原像素位置。

没有做好的部分：

- 当前是逐行贪心选峰，不是全局动态规划/Viterbi；
- 没有 Steger/Hessian 亚像素脊线；
- 已消除“平顶下降沿固定窗口”造成的中心偏移，但仍没有把平顶、条纹膨胀、
  双峰、次峰、散斑和多径反射分类为独立质量状态；
- 低置信度门槛 `0.05` 很宽松；
- 没有相邻帧条纹/三维轮廓时序一致性；
- 没有工作空间裁剪、统计离群、半径离群或法向一致性；
- 没有将高反光异常点与普通几何点分开标记；
- `line_quality_warning` 使用单帧轮廓对最佳直线的 RMS，曲面和台阶也必然报警，不适合作为普通工件质量门槛。

### 4.6 连续点云线程和文件输出

当前连续点云采用：

- 2 个固定重建线程；
- 64 帧固定容量队列；
- 同步回调使用 `try_lock` 无等待入队；
- 队列满或锁竞争时只丢该帧重建任务，不反压相机和 FR5；
- 扫描停止后再保存 raw/voxel PLY。

当前实测没有重建队列丢弃，线程数合理。

需要改进：

- 所有帧结果和全部点目前保存在内存中，长时间扫描会线性增加内存；
- 输出是 ASCII PLY，体积和保存时间都大；
- 建议改为分块二进制临时文件或流式二进制 PLY/PCD，结束时写最终头；
- 原始点云和显示点云应分开：原始点用于计量，体素/滤波云用于显示；
- 当前只有体素平均，没有保留每个体素内方差、观测次数和质量；
- 没有实时点云预览，错误通常在扫描完成后才发现。

### 5.5 100 mm 游标卡尺初步验证

CloudCompare 截图中的测量分量为：

```text
Distance = 99.173854 mm
ΔXY     = 99.163826 mm
ΔZ      = 1.410027 mm
真值名义 = 100.000000 mm
误差      = -0.826146 mm
相对误差  = -0.826146%
单次比例  = 100 / 99.173854 = 1.00833028
```

这次结果说明整条“激光重建 + 手眼 + 同步 + 多帧拼接”链路已经接近正确尺度，
也第一次暴露出约 0.8 mm/100 mm 的实际偏差。但它不能证明系统需要直接乘
`1.00833028`，原因包括：

- 游标卡尺是高反光金属，激光中心可能受饱和、散斑和多径影响；
- 当前是 CloudCompare 人工两点，不是对两端基准面/边缘做几何拟合；
- 两端各偏 1–2 px，在当前工作距离就可能形成约 0.5–1 mm 的长度变化；
- 只有一次扫描，没有均值、标准差、正反向差异或跨深度数据；
- 卡尺显示 100 mm 不是带证书的长度标准，零位和测量基准面仍需确认；
- 多帧连续点云同时包含激光面、手眼、机器人姿态和同步误差，不能仅归因于
  激光平面。

下一步应使用哑光量块、阶梯标准件或给卡尺贴哑光材料，分别拟合两个基准几何
特征；在 350/500/700/900 mm 深度、正反两个方向各重复至少 5 次，并使用
50/100/150 mm 多个长度拟合：

```text
测量值 = a × 真值 + b
```

只有当比例误差跨长度、深度和方向保持稳定时，才能讨论尺度修正。不能直接缩放
`base_link` 中的全部点，因为那会同时错误缩放机器人运动和平移原点。

如果机器人在两个 12 ms 样本间保持常加速度，线性位置插值的理论最大偏差约为：

```text
a × Δt² / 8
= 100 mm/s² × (0.012 s)² / 8
≈ 0.0018 mm
```

这只说明“常加速度数学插值误差”很小，不包含控制器位姿量化、伺服跟随误差、结构振动、robotTime 量化和时间轴固定偏差。

### 7.2 尚不能量化的主要误差

- FR5 实际绝对定位精度和当前姿态下重复性；
- 相机/激光支架在运动、加减速和线缆拉力下的挠曲；
- 机器人、相机和激光器热漂移；
- 镜头畸变在视场边缘和不同工作距离的残余；
- 激光线宽、散斑、表面反射和多径造成的中心偏移；
- 相机时间戳相对于真实曝光事件的固定偏差；
- 激光平面在长期运行后的机械漂移；
- 手眼旋转误差对当前工作距离的实际放大；
- 高反光假条纹产生的非高斯大离群点。

这些误差不能通过把现有 RMS 直接平方和得到。必须依靠独立标准件和重复实验识别。

连续 PLY 中背景差分响应达到 250 以上的点约占 41%–47%。该响应不完全等同于原图饱和比例，但同样说明大量条纹已接近 8 bit 上限。

因此当前点云即使总体形状正确，局部仍可能存在：

- 超过 20 px 或不对称饱和平顶造成的剩余中心偏移；
- 镜面高光被误认为激光峰；
- 第二亮边或多径反射被选为主条纹；
- 连续但错误、且深度仍处于合法范围内的假点。

#### P2-4 J6 纯旋转连续扫描

方案在几何上可行：J1–J5 保持不变，仅改变 J6，法兰原点 XYZ 理论上基本
不变；但相机光心通常偏离 J6 轴，会沿圆弧运动。只要手眼正确，现有
`T_base_flange · T_flange_camera` 和曝光中点 SLERP 可以处理该刚体运动。

当前不能直接启用：

- 连续 GUI 只发送物理速度 MoveL；
- 恒速检测只拟合 XYZ 线速度；
- 纯旋转会被判为 `STOPPED/SPEED_NOT_STABLE`；
- 当前线间距公式是 `mm/s ÷ fps`，不适用于角运动；
- “同 XYZ、不同 RPY 的 MoveL”不能保证只有 J6 运动。

需要新增独立模式：

1. 读取并示教 J6 起止角，锁定 J1–J5；
2. 使用控制器关节运动接口，以 `deg/s` 指定恒定 J6 角速度；
3. 从逐包状态记录关节角和法兰姿态；
4. 用 J6 或四元数角速度判断加速、恒速和减速；
5. 线间距使用 `s ≈ R × ω / fps`；
6. 曝光模糊使用 `b ≈ R × ω × exposure`；
7. 检查 J6 限位、奇异性、扫描头碰撞和线缆扭转；
8. 用正反向旋转验证固定时间偏差和手眼旋转误差。

60 fps 下的量级：

| 物体到旋转轴距离 | 0.2 mm 线间距 | 0.5 mm 线间距 |
| ---: | ---: | ---: |
| 500 mm | ≤1.38°/s | ≤3.44°/s |
| 1000 mm | ≤0.69°/s | ≤1.72°/s |

第一轮建议约 `1°/s`、±20–30°。如果 J6 轴与相机光轴近似重合，运动可能只
让画面滚转而不扩大覆盖范围，必须先用安装几何和小角度 dry-run 验证。
旋转扫描对手眼角误差尤其敏感：`0.1°` 在 500 mm 杠杆处约为 `0.87 mm`。

| 激光配置状态 | 650 文件位于 `config` | 450 四份文件位于 `config/devices/scanner_450/`，两套独立启用 |
| 系统边界 | README 前部偏重停稳扫描 | 当前已实现连续同步点云 |
| 旋转扫描 | 尚无正式说明/界面 | 当前仅 MoveL；J6模式只是设计方案 |

建议把硬件参数集中到一个 `config/system_inventory.yaml`，程序启动时读取并将快照复制到每个 session，避免文档、GUI默认值和实机逐渐偏离。

## 15. 最终判断

当前系统的主要工程难题已经不再是“相机和机器人线程能不能同时跑起来”。这部分已经有了可靠基础：

- 60 fps 稳定；
- 83.3 Hz FR5 完整包稳定；
- 曝光中点位姿插值链路存在；
- 数据入口与写盘/重建基本解耦；
- 连续点云能够自动输出；
- 300–1000 mm 激光标定采集、复算和近端宽条纹问题已经得到实机验证；
- 第一次 100 mm 长度检查得到 99.173854 mm，为后续误差拆分提供了起点。

下一阶段应把资源集中到五个方面：

1. **恢复新激光面的可信数据链并补齐 300 mm 的第 5 组，重新由 GUI 正式批准；**
2. **用哑光标准件、几何拟合和重复正反扫给整机精度定量，而不是根据一次
   卡尺人工选点或点云外形修改尺度；**
3. **标定固定时延并强化手眼，消除主要系统误差；**
4. **对高反光建立真正的质量检测、拒绝和重扫闭环；**
5. **若开发 J6 快速建图，必须增加关节角速度模式、角采样质量判定和线缆/
   碰撞安全检查，不能复用现有线速度 MoveL 门槛。**

完成这些项目后，系统才能从“可工作的连续线激光扫描原型”进入“精度和失败
模式可解释、可复现、可验收的测量系统”。
